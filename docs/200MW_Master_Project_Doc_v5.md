## WHAT THIS APP IS
AI-powered early literacy app (ages 4–8) built on **Dr. Marion Blank's methodology**. 200 foundational words across 18 units, adaptive games, ElevenLabs audio, Candy Galaxy theme, Nova the Comet Spark. Freemium: Units 1–5 free, 6–18 on Family Plan ($9.99/mo / $79/yr — Stripe checkout built + verified, still TEST mode).

### CORE METHODOLOGY RULE (non-negotiable, every prompt)
Dr. Blank is **anti-phonics**. NEVER sound-blend / sound out anywhere ("cuh-a-tuh" confuses early readers). Words are whole units tied to meaning: Find the Word, cloze-in-context, repeated meaningful exposure, whole-word recognition. Struggle is met by scaffolding DOWN the demand, never by drilling phonemes. **This cycle's sharpest reminder of the stakes**: a brand-new child's freeform-generated story ("Aliya cat.", "Cat cat.", "Aliya cats.") both violated whole-word-only teaching (an inflected "cats" that isn't one of the 200 words) *and* was simply not language — see Story Engine below.

15. **FIX_CELEBRATION_R1 — star-ignition timing fix** (merged `7e355dc`). Root cause: `GameEngine.handleAnswer` fired `onProgress` (→ `PlayScreen.handleProgress`, which awaits a real Supabase write before queueing the celebration) **without awaiting it** before proceeding to `onSessionEnd` on the session's last question — the orphaned promise could resolve after the screen already swapped to `SessionComplete`, landing the celebration on whatever screen the global `CelebrationRenderer` overlay happened to catch next (worst case: a bare "Loading your galaxy…" screen with zero chrome). Fixed by awaiting that promise before ending the session (`GameEngine.jsx`), a `sessionEndedRef` backstop gate on `queueCelebration` (`PlayScreen.jsx`), and a new client-side `src/lib/celebrationDedup.js` (localStorage-keyed per child/word/day — cumulative mastery isn't a one-way ratchet, so a same-day re-cross needs its own dedup, not a migration). Verified: repro gap 2815ms → 0ms; production walk showed ignition ~1839ms after the answer, anchored inside the still-active activity.

16. **FEAT_PEDAGOGY_CALIBRATION_R1 — mastery gate + scaffold-down v1 + attempt wiring** (merged `633d68e`). Three independent pieces:
    - **Mastery gate**: `isRealMastery` (already established by Package A) rolled out to 14 remaining consumers that still used a naked `mastery >= 80` check (client screens + `api/session-generator.js`). Stored formula, raw `percent`, and unit-number gates untouched. Server side is CommonJS and can't import the ES-module constants, so `api/session-generator.js` mirrors them; `scripts/check-mastery-predicate-sync.mjs` (wired into `npm run build`) asserts numeric identity so the mirror can't silently drift.
    - **Scaffold-down v1**: two completed errors on the same word (tracked session-locally in `PlayScreen.jsx`) pins that word's Guided Path node to a derived easier activity (first entry of the word's existing `getEligibleActivities` ranking — `word_match` for has-art content words, `rhyme_time`/`find_the_word` otherwise) and shows a persistent non-punitive banner. A correct completion at the pinned activity clears the pin. Logs `scaffold_down` to `product_events` (`api/track.js`).
    - **attempt_number wiring**: `learning_events.attempt_number` existed in schema but every insert hardcoded `1`; now writes the real post-write attempt count from `useSaveWordProgressMutation`'s own return value. **Forward-only — historical rows before this deploy keep literal `1`.**
    - Also folded in: the `weeklyStats.js` same-screen fix (both derivations now threshold/attempt-gated, matching chart 1) and a chart-1 84-day-window truncation guard (`computeWeeklyMasteryCrossings` now discards a crossing whose replay-final counts don't match the word's real all-time stored counts, rather than risk a false "fresh crossing" off a fetch-window edge).
    - **Hard-won lesson, load-bearing for every future `product_events` type**: adding a new event name to `api/track.js`'s client allowlist is not sufficient — the `product_events_event_type_check` CHECK constraint (a migration) must be updated in the *same* change, or inserts silently fail (fire-and-forget, `console.error` only, endpoint still returns 200). This bit `scaffold_down` itself (zero rows landed for a while, caught by `idor-proof.mjs`), and is exactly the same class of gap this cycle's Story Engine telemetry deliberately avoided (item 21) by reusing an already-correctly-wired event type instead of adding a new one ungated.

20. **PERF_ACTIVITY_LOAD_R1 — tap-to-playable AI-call latency** (merged `93bf99c`). Root cause: cold-tap latency (~7.1s median) is ~92–95% `/api/session-generator`'s own server time, and within that endpoint the blocking Anthropic call for flavor text (not word/activity *selection*, which is 100% deterministic and fully computed before the AI call ever fires) is the dominant cost. Three selection-neutral fixes shipped: (a) client-side cached-plan reuse on a focus-word tap (`reorderPlanForFocusWord` — a real pre-existing double-fetch bug fixed: every word tap fired two calls to `generatePlan`, discarding a valid cache even when one existed); (b) Home-mount prefetch (`prefetchSessionPlan`, restoring the session-plan hook's own documented "generate once at login" intent, which had drifted since the hook only ever lived inside `PlayScreen`); (c) server-side parallelization of `fetchChildContext`'s two independent reads. **Net effect**: cold tap is deliberately unchanged (~7-12s, noisy, AI-call-bound); a warm/prefetch-covered tap dropped from firing the AI call *at the tap* to firing it *during the preceding dwell* — production-verified `wordTapToPlayableMs` 5766ms with the session-generator call already in flight before the tap, not after. **Deliberately left untouched, per Sal's explicit instruction**: the blocking Anthropic call itself and its AI-chosen `sessionLength`. Three named options logged for a future pass (always use the deterministic `defaultLength` fallback; cap the AI call with a timeout degrading to that fallback; proactively regenerate the plan in the background post-session) — plus a separate, explicitly-flagged-as-pedagogy-not-perf open question: should AI-chosen `sessionLength` exist at all vs. a fixed per-difficulty number.

21. **FIX_STORY_QUALITY_R1 + FIX_STORY_FOLLOWUP_R1 — the Story Engine no longer produces non-language** (merged `9115eb0`, then `eac7a0b`). A brand-new child (pool size 1, the *normal* first-session state under the mastery-gate floor, not an edge case) received a degenerate freeform-Story-Engine story ("Aliya cat.", "Cat cat.") while a hand-authored `story_catalog` story for the same word sat unreachable from that surface. Reproduced live on production first: the AI call did **not** fail — it succeeded legitimately on a retry against an artificially 1-word vocabulary pool, and an inflection-permission rule (`stripsToAllowed`, "cats" counts as valid given "cat") let a non-200-word token through. Fixed in two passes:
    - **Quality floor + routing** (`FIX_STORY_QUALITY_R1`): `MIN_MASTERED_WORDS_FOR_GENERATION = 4` (`src/lib/queries/stories.js`) — below this, `StoryScreen.jsx` never calls the AI at all, instead serving `story_catalog` content (new `findCatalogStoryForWord`, tries the child's real tier then falls through 3→2→1, since production catalog coverage today is 100% tier-3) or a small guaranteed-safe local template as last resort. `api/story-engine.js`'s `validateStory` now requires exact word-list membership — no inflection loophole — for the AI path.
    - **Follow-up** (`FIX_STORY_FOLLOWUP_R1`, Sal-decided): the first pass's catalog-vocabulary gate was removed — curated content's richer read-aloud vocabulary ("yard", "paw", "nap" in "The Curious Cat") is the methodology, not a violation; that strictness stays only on the AI path. A brand-new child targeting "cat" now receives **"The Curious Cat" verbatim** from `story_catalog`. Also replaced a `scaffold_down` telemetry reuse (added by the first pass) with a plain `console.warn` — that write was polluting the pedagogically meaningful signal item 16 established; a proper fix needs a new `product_events` type, deliberately deferred to a migration (see OPEN ITEMS).
    - **A real, separate, unresolved finding surfaced while building this fix's own test**: `story_catalog` content itself is not guaranteed to stay inside the 200-word list (confirmed word-by-word against the real `words` table, not assumed) — see OPEN ITEMS.

## TRAPS REGISTRY
Consolidated and deduplicated from every report's own TRAPS section this cycle (`CELEBRATION_FIX_REPORT.md`, `BLANK_ENGINE_REPORT.md`, `ACTIVITY_LOAD_PERF_REPORT.md`, `NO_BLANK_SCREENS_REPORT.md`, `PEDAGOGY_CALIBRATION_REPORT.md`, `PLACEMENT_CHECKIN_REPORT.md`, `STORY_QUALITY_REPORT.md`, `STORY_FOLLOWUP_REPORT.md`, `QA_HARDENING_REPORT.md`) plus v4's own "HARD-WON SESSION RULES." Grouped by theme, not chronological.

**Environment / worktrees**
- `.env.local` is gitignored and does not carry over into a fresh `git worktree add` — copy it in manually before `npm run build`/`preview`/any Supabase-touching script, every time.
- `git worktree` is the fast, non-destructive way to check "does this failure pre-exist on `main`" (or on a fresh checkout at all) without disturbing your current branch's state — used repeatedly this cycle to separate real regressions from pre-existing flakiness.
- `git checkout <ref> -- .` (working-tree-only, no branch switch) is a lighter-weight variant of the same idea inside one worktree — remember to `git checkout HEAD -- .` immediately after, and `git status --short` before/after both times.
- Never edit source files while a background full-suite Playwright run against the same working tree is still executing — even across a `git commit`. The dev server serves live file contents from disk, not the git-committed snapshot.

**Supabase / product_events / migrations**
- Adding a new client-facing event name to `api/track.js`'s allowlist is NOT sufficient by itself — the `product_events_event_type_check` CHECK constraint (a migration) must land in the *same* change, or inserts silently fail (fire-and-forget, `console.error` only, HTTP 200 either way). Bit `scaffold_down` once already; the lesson is now explicitly load-bearing for every future event type.
- Two client-originated event types in the same PR/migration need BOTH the CHECK constraint AND the `api/track.js` allowlist entry in one commit; a server-only event type (like `checkin_started`) needs only the CHECK constraint.
- `child_profiles`'s table-level `REVOKE UPDATE` (migration 0033) only blocks `authenticated`/`anon` roles, never `service_role` — a real, useful affordance for seeding otherwise-client-unwritable test-fixture columns directly via the admin client.
- Supabase selects cap at 1000 rows — page with `.range()` or truncate silently (bites the most active kids first).
- A migration file's number is only unique per-branch until merge — check unmerged branches (not just `main`) before numbering a new one; this cycle found a live collision (see OPEN ITEMS).

**Testing / Playwright**
- `SUPABASE_SERVICE_ROLE_KEY` must be exported in-shell — `npx playwright test` without it silently *skips* every account-provisioning spec (`test.skip(!SERVICE_KEY,...)`) rather than failing, producing a falsely-reassuring high pass rate. Compare pass/fail counts across runs only when this was set identically both times.
- A production-baseURL-locked spec (`test.use({baseURL: "https://200magicwordsapp.com"})`, or `DEPLOY_BASE_URL` defaulting there) can never exercise an unmerged branch's code — check for this override before blaming your diff for a spec failure.
- `waitFor({state:'hidden'})` resolves immediately for a never-attached element, not just an invisible one — always wait for a positive rendered signal instead of a negative one.
- `fullPage: true` Playwright screenshots smear `position:fixed` elements across stitched scroll frames — never trust an apparent fixed-nav overlap from a full-page screenshot alone; re-capture `fullPage:false` at the real scroll position before logging it as a bug.
- Fixed `waitForTimeout` delays are a known source of flaky screenshots/assertions — prefer a real element-visibility/enabled-state wait every time, even when it's more code.
- WordArt/tile accessible names combine icon + visible text (e.g. "cat cat") — exact-match role queries fail; use an anchored or unanchored regex instead.
- Ambiguous button text (e.g. two elements both literally named "Sign in") throws a Playwright strict-mode violation — disambiguate via a more specific selector (`button[type="submit"]`) rather than relying on name alone.
- `admin.generateLink` produces implicit-flow links that PKCE rejects — use `verifyOtp({token_hash})` instead. Admin-created fixtures still need `parental_consent` metadata or they hang on the COPPA interstitial.
- A Playwright hard test-timeout aborts without unwinding `try/finally` — cleanup can be skipped specifically in a timeout-abort case; check for orphaned accounts after any timeout failure.
- A shell command with backticks inside a single-quoted `git commit -m "..."` string will command-substitute — avoid raw backticks in commit messages passed via `-m`.

**App-specific gotchas**
- Modules importing `supabaseClient.js` can't load under Playwright's/Node's plain module loader — extract pure logic to zero-import files in `src/lib/` (the established pattern: `masteryCalibration.js`, `starKeeper.js`, `checkinEligibility.js`, `streakFreeze.js`).
- `import.meta.env` inlines at dev-server start — env-gated UI needs its own Vite instance to test a different flag state.
- The Grown-Ups hold-gate needs real Playwright `page.mouse.down()`/`up()` around a wait — its rAF timer doesn't advance under synthetic `dispatchEvent`.
- Vite dev-mode's native-ESM live-binding throws hard on a missing named export (even if unused); Rollup's production build silently tolerates the same gap. A stale dead import can crash the *entire* dev-mode React tree (every route) while `npm run build` and every production walk stay green — invisible until someone runs the dev server. Cost one workstream over an hour of misdiagnosis (initially blamed on memory pressure) before console-capture revealed the real cause.
- A pool/candidate array's element ORDER matters when later truncated with `.slice(0, N)` — appending a small reserved sample to the end of an unbounded-source array risks silent starvation of that sample; verify it survives the cap with a live call, don't assume.
- The local client-fallback session plan and the real server-side `api/session-generator.js` select candidate words differently (sort order, mastered-word inclusion) — a fixture built against one won't reproduce the same shape against the other.
- Rate limits are shared per authenticated user across every mode of a multi-mode endpoint (`session-generator`'s 10/min covers plain/`reviewOnly`/`placementMode`/`checkinMode`/`historyMode` alike) — a verification script spending one identity's budget on negative-path checks can starve a positive multi-step flow on the same token.
- `.select()` queries in test/audit scripts should verify against the LIVE table state at cleanup/verification time, not trust an earlier report's snapshot — an unexplained account cluster is a real signal worth re-checking, not noise to ignore.
- Never trust a "hand-authored"/"curated" label as an automatic guarantee of "vocabulary-safe" or otherwise-compliant — verify content word-by-word against the actual rule, the same rigor applied to generated content.
- A pool of size 1 (or an empty mastered-word list) is not an edge case for this app — it is the default state of every brand-new account under the mastery-gate floor. Any future feature that personalizes from "mastered words" must design for that as the *common* first case.
