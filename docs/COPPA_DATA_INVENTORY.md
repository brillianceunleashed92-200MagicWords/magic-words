# COPPA Data Inventory

Compiled during `security-hardening` branch work as a code-level starting point for
Sal's legal review — **this is not a substitute for counsel**. It answers "what data
does the code actually collect and where does it actually go," verified against the
live schema and source, not assumed from a product spec.

## Child data collected

| Data | Where stored | Collected via | Notes |
|---|---|---|---|
| First name | `child_profiles.name` | Parent types it at onboarding (`ChildOnboardingScreen.jsx`) | Capped at 40 chars. No last name field exists anywhere. |
| Avatar (icon choice) | `child_profiles.avatar` | Parent picks from a fixed set of illustrated icons | Not a photo — a stored icon-id string, e.g. `rocket`. |
| Interests (up to 3) | `child_profiles.interests` | Parent picks from a fixed, moderated list (`src/lib/interests.js`) | No free text — closed list only. |
| Age | `child_profiles.age` | Column exists in schema | **Not currently collected anywhere in the live onboarding flow** — grepped, no UI writes this field. Present but unused. |
| Word mastery / progress | `word_progress`, `user_stats`, `user_streaks` | Generated by gameplay | No text/audio, just word + score + timestamps. |
| Drawings (Draw It activity) | Supabase Storage `drawings` bucket, path `{parent_user_id}/{child_id}/...` | Child draws on-screen, PNG saved | The only actual "content" a child creates that's persisted. Private bucket, parent-owned RLS. |
| Magic Moments (drawing/story/streak highlights) | `magic_moments` | Generated by gameplay, references the above | Metadata + references, not new raw content. |
| Generated stories | `stories` | AI-generated (see below), saved per child | Story text only — vocabulary-controlled, no free-form child input in the story itself. |
| Speech (Say It with Nova) | **Nowhere** | Browser's native Web Speech API, transcript compared in-memory | Verified directly in `SayItWithNova.jsx`: the transcript is used for one boolean comparison (`heard`) and never referenced again — no audio blob, no transcript string, ever reaches a server or gets written to Supabase. This session's audit confirmed this by reading the full component, not assuming it. |
| First-party analytics events | `product_events` (migration 0032, extended 0034) | Server-side (`placement_*`, `checkout_started`) or client-originated via `/api/track` (`paywall_viewed`, JWT-verified) | ids + enum values only — `user_id`, `child_id`, and a closed set of payload keys (e.g. `surface`, `interval`, `placementUnit`). No child name, no free-form text of any kind. Service-role-only table, no client read/write RLS policy. See `docs/ANALYTICS.md` for the full event taxonomy. |

## Parent data collected (for completeness, not the primary COPPA concern)

Email, password (hashed by Supabase Auth, never touched by app code), Stripe
customer ID + subscription status (`subscriptions` table), daily time-limit
preference (`parent_settings`).

## Third parties child data flows to

| Third party | What it receives | Why | Persisted by them? |
|---|---|---|---|
| **Anthropic (Claude)** | Child's first name (≤40 chars, capped harder to 3 words after this session's prompt-injection fix — see `docs/SECURITY_CHECKLIST_FOR_SAL.md` Phase 4), 1-3 interest category labels (from a closed list, e.g. `"dinosaurs"` — never free text), the current target vocabulary word, and a rolling list of mastered word/mastery-score pairs (`api/story-engine.js`, `api/session-generator.js`, `api/parent-digest.js`). **No email, no child UUID, no age, no last name, no avatar choice, no location, no device info.** | Generates the personalized decodable story, the session's word sequence/difficulty, and the parent's weekly digest text. | Per Anthropic's API terms, not persisted for model training by default on API (non-consumer) usage — verify current terms before relying on this, they can change. |
| **ElevenLabs** | The literal text string being spoken (a vocabulary word or a fixed question-template sentence, e.g. `"Which picture shows a cat?"`) — no child name, no identifiers of any kind (`api/speak.mjs`). | Text-to-speech audio generation. | Generated audio is cached in this app's own Supabase Storage (`word-audio`, `tts-cache` buckets) specifically so the *same* text is never sent to ElevenLabs twice — reduces repeat exposure as a side effect of the Phase 5 cost-control work, not just a privacy feature. |
| **Stripe** | Parent's email (for checkout), never the child's name or any child data at all. | Payment processing for the paid plan. | Stripe's own data retention/PCI-DSS scope — this app never sees or stores raw card data either way. |
| **Vercel** | Standard request logs (IP, timestamp, path) for every request, same as any web host. | Hosting/infrastructure. | Governed by Vercel's own log retention, not something this app's code controls. |
| **Supabase** | Everything in the table above (it's the database) + auth session data for the parent. | Primary data store. | Supabase's own DPA/compliance posture (SOC 2 etc.) — the row-level-security work elsewhere in this session controls *who inside the app* can read it, not Supabase's own operational access. |

## What is explicitly NOT collected

- No child email, phone number, or any direct contact info — a child never has
  their own account or login in this app's model; only the parent authenticates.
- No precise geolocation (confirmed: `Permissions-Policy: geolocation=()` blocks
  it at the browser level as of this session's Phase 6 work, and no code path
  requests it).
- No camera access (same header blocks it; no code path requests it).
- No third-party advertising/analytics SDKs of any kind — grepped the whole
  dependency tree for common ad/analytics packages (Google Analytics, Facebook
  Pixel, Mixpanel, Segment, etc.) — none present.
- No persisted speech audio or transcripts (see table above).

## Open items for Sal / legal review

1. **`child_profiles.age` is an unused schema column.** If age is ever collected
   in the future (even just an age band, not a birthdate), that changes the
   COPPA analysis (age-gating, verifiable parental consent requirements scale
   with how precisely you know a child's age). Currently moot since it's never
   written.
2. **The consent checkbox added this session** (see below) records *that* a
   parent clicked it and *when*, but is not a substitute for whatever specific
   verifiable-parental-consent (VPC) mechanism your counsel determines this
   product needs under COPPA §312.5 (email-plus, signed form, payment-card
   verification, etc.). Flagged as a real gap, not solved by a checkbox.
3. **`/privacy` and `/terms`** (added this session) are explicitly marked DRAFT
   placeholder content — real policy language needs to come from counsel before
   this product handles real payments in live Stripe mode.
4. **Data retention / deletion**: the account-deletion flow added this session
   (Settings → "Delete account & all data") cascades every table and Storage
   object listed above, plus the auth user itself. Worth confirming with counsel
   whether COPPA's requirements around timely deletion upon parental request are
   fully met by an immediate, parent-self-service delete, or whether a formal
   request-and-confirm workflow (e.g. via a support email) is also needed
   alongside the in-app button.
